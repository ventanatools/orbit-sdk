# Changelog

Every notable change to the packages in this repository is listed here. The
format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the
packages use [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before
1.0 any minor version may break (contract §12.2); every break is listed.

The packages are `VentanaTools.Orbit.Extensions`, `.Testing`, `.Hosting`, `.Tool`
and `.Templates`, and the unpublished Node SDK `@ventanatools/orbit-extensions`;
they version in lockstep.

## [Unreleased]

Nothing yet.

## [0.1.0-preview.1] - not yet released

Contract generation 3. Every file format and the wire protocol move to their next
version, and version 2 of every format is withdrawn: hosts and SDKs of this
generation refuse a schema-2 manifest, a version-2 pairing file, a `package.json`
descriptor and a protocol-2 `hello` with a stable code. This preview replaces the
protocol-2 source preview, `Orbit.Extensions.Protocol` and `Orbit.Extensions.Sdk`
0.1.0-preview.2; the new package IDs start again at 0.1.0-preview.1.

### Breaking changes from Orbit.Extensions.* 0.1.0-preview.2

**Packages and names**

- `Orbit.Extensions.Protocol` and `Orbit.Extensions.Sdk` are merged into one
  author package, `VentanaTools.Orbit.Extensions`. Its root namespace,
  `VentanaTools.Orbit.Extensions`, holds everything an author names; hosts and
  tools use `VentanaTools.Orbit.Extensions.Packaging` and
  `VentanaTools.Orbit.Extensions.Wire`. Replace both package references with
  one, and both `using` directives with `using VentanaTools.Orbit.Extensions;`.
- The copyright holder is Ventana Tools LLC. The libraries and tools stay
  Apache-2.0; the samples are now MIT-0.
- The local package folder is `artifacts/packages` (was `artifacts/extension-sdk`),
  and `NuGet.config` maps `VentanaTools.Orbit.Extensions*` to it.

**Manifest schema 3** (`extension.json`)

- `schemaVersion` is 3. A schema-2 manifest gets `schema.version-unsupported`.
- A contribution's `capabilities` is renamed `provides` (`["invoke"]`,
  `["face"]` or both); the old name, and `manifestVersion`, get
  `json.member-renamed`.
- New optional members: `$schema`, `glyph`, `publisher`, `supportUrl`,
  `defaultLanguage`, `disclosures` and `requires`. Setting rows gain `kind`
  (`Choice`) and an optional `description`.
- Ids: the extension id must contain a dot; it may not start with a reserved
  publisher (`orbit`, `pinwheel`, `lollipop`, `ventana`, `ventanatools`, `ext`)
  or a Windows device name; a manifest with one contribution may use the
  extension id itself as the contribution id.
- Every human-readable string follows the declaration text rule: no controls,
  bidirectional overrides, invisible format characters or noncharacters. Glyphs
  are one private-use character; URLs are absolute `https`.
- Localized strings files, `strings/<language-tag>.json`, are new.

**Diagnostics**

- Every reader reports `Diagnostic` values in the Ventana diagnostics shape:
  a stable dotted `code`, a JSON Pointer `path`, a fixed `message` that never
  echoes file content, a `severity`, the `file`, and the `line` and UTF-8 byte
  `column`. Readers collect every finding (up to 200), one per path, instead of
  stopping at the first.
- Reads return `ReadResult<T>`; `ManifestReader`, `StringsReader`,
  `PairingReader` and `PackageReader` have bounded `ReadFileAsync` methods.
  File-system failures surface as exceptions, content problems as diagnostics.

**Package archive version 2**

- The descriptor `package.json` is renamed `extension.package.json`, carries
  `archiveVersion` 2, the manifest hash and a SHA-256 inventory of every file,
  and is generated by tools.
- Stricter archives: ZIP64 and encryption refused, every local header must
  match its central record, no bytes outside the records, a path grammar, and
  limits for every part. `README.md` is required; `strings/` is new.
- The package file name is `<id>-<version>` with the host's package file
  extension.

**Pairing file version 3**

- `pairingVersion` 3 replaces `protocolVersion`; new members `mode`
  (`Persistent`) and `hostId`. The pipe name, the secret and every member are
  checked against the manifest.
- The default location is per user:
  `%USERPROFILE%\.ventana\pairings\<host-id>\<extension-id>.pairing.json`.
  `ExtensionPairing` is replaced by `PairingReader` and a disposable `Pairing`
  that never exposes its secret.

**Wire protocol 3**

- The pipe prefix and proof label `Orbit.Extensions.v2` become
  `Ventana.Extensions.v3`, and the pipe name gains the host id.
- The handshake is `hello`, `challenge`, `authenticate`, `ready`: version
  negotiation, capability lists, and mutual HMAC-SHA256 proofs over a transcript
  that binds both offers, the host's id and version and the manifest hash.
  `ready` carries the host's UI language and limits.
- New messages: `error` with an open registry of reason codes, `ping` and
  `pong`, and `sessionRefused`. Handshake frames are limited to 8 KiB; rate
  limits are token buckets charged per started KiB; unknown optional members and
  message types are ignored under fixed rules.
- Failure tokens: `UnsupportedInput`, `NeedsSetup`, `Network`, `NoResult`
  (replaces `NoData`) and `AppUnavailable` (new).

**The .NET client**

- `CompanionClient`, `CompanionConnection`, `CompanionMessages` and
  `CompanionContracts` are replaced by `CompanionApp.RunAsync(args, handler)`,
  `ContributionHandler`, `ContributionRouter` and a new `CompanionClient` with
  `ConnectionState`, `StatusChanged` (reason codes, backoff with jitter, and
  server verification) and `HandlerFaulted`.
- `Session.SetFace(Face)`, `ClearFace()` and `Fail(Failure)` return
  `PublishResult`; face text is cleaned instead of refused; one pending face per
  session; opt-in renewal with `Face.Renew`. Invocations return `InvokeResult`.
- Removed: `ExternalExtensionManifest`, `ExternalExtensionAction`,
  `ExternalExtensionSetting`, `ExternalExtensionChoice`,
  `ExternalExtensionSettings`, `ExternalExtensionPackage`, `ExtensionPairing`,
  `ExtensionWire`, `ExtensionJson` and `ExtensionText`. Their replacements are
  `ExtensionManifest`, `Contribution`, `Setting`, `SettingChoice`,
  `Packaging.PackageReader`, `PairingReader`, the `Wire` namespace and
  `TextRules`.

**Tools and samples**

- `tools/extension-package` and `orbit-package.json` are gone. Packages are
  built by `orbit-ext pack` from `extension.pack.json`.
- The samples moved to protocol 3. The Photoshop sample uses the Node SDK and
  product-neutral identifiers (plugin id `example.photoshop-bridge`, WebSocket
  path `/photoshop-bridge`), and reports `AppUnavailable` when Photoshop is gone.
- `tools/build.ps1` and `tools/verify.ps1` run on Windows PowerShell 5.1 as well
  as PowerShell 7; local builds are stamped `0.1.0-dev.<UTC timestamp>` and the
  samples restore into a fresh folder per build.

### Added

- `VentanaTools.Orbit.Extensions.Testing`: `RecordingSession`,
  `CompanionTestHost`, `ContributionContractSuite` and `ExtensionConformance`.
- `VentanaTools.Orbit.Extensions.Hosting`, the Generic Host add-on:
  `services.AddCompanion<THandler>()` (or a handler factory) runs a companion as
  a hosted service with `CompanionApp`'s discovery, status and exit codes, logs
  each status through `ILogger` with a fixed event id, and stops with the host.
  The tool carries it into the feed `orbit-ext new` prepares.
- `VentanaTools.Orbit.Extensions.Tool`, the `orbit-ext` command: `new`,
  `validate`, `pack`, `verify`, `test`, `simulate`, `run`, `link` and `schema`,
  with MSBuild-style and JSON output.
- `VentanaTools.Orbit.Extensions.Templates`: `orbit-ext-action`,
  `orbit-ext-widget` and `orbit-ext-node`.
- `@ventanatools/orbit-extensions`, the Node SDK (unpublished).
- JSON Schemas for the manifest, strings, package descriptor, pairing, pack and
  simulation files.
- The golden test vectors of the contract's Appendix A in `fixtures/`, shared by
  the .NET SDK, the Node SDK and the host, and the host-id registry
  `fixtures/hosts.json` (`HostRegistry`). `fixtures/text-rules.json` also states
  the declaration text limits as a Ventana convention (`declarationLimits`: 80
  UTF-16 units for a name or label, 512 for a description, `text.long` past 32
  text elements), which both SDKs' readers and the schemas are tested against.
- Public API tracking, package validation, SourceLink, symbol packages, and
  release notes that link to the version's section of this changelog.
- CI: CodeQL, Dependabot, a Native AOT publish of the Countdown sample, and a
  release workflow that builds, tests, packs and validates without publishing.
- `eng/rename-product.ps1` and `tools/Set-HostCodename.ps1`, the scripted
  product rename.
